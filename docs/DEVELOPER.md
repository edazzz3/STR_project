# 🛠️ Техническая документация

Файл для разработчиков. Описывает архитектуру, структуру модулей, ключевые
контракты данных и внутренние решения.

---

## Стек

- **Vanilla JS** — ES-модули, `<script type="module">`.
- **Без сборщиков** и пакетных менеджеров.
- Библиотеки через CDN:
  - **Three.js** `0.160.0` — через `importmap` (`three`, `three/addons/`).
  - **pdf.js** `3.11.174` — глобальный `window.pdfjsLib`.

## Состояние (`js/state.js`)

Единый объект `state` — один источник правды.

```js
state = {
  layers: [],       // массив слоёв: pdf | str | txt
  activeId: null,   // id активного слоя (подсвечен в панели)
  mode3d: false,    // текущий режим
  labelConfig: {},  // какие поля показывать у точек: { [id]: { fields, round } }
  theme: 'light',   // 'light' | 'dark'
}
```

### Контракт слоя

```js
// PDF
{ id, kind: 'pdf', name, visible, locked,
  canvas, width, height, affine, userAffine, pageNum, pageCount }

// STR/TXT
{ id, kind: 'str'|'txt', name, visible, locked,
  pts, groups, header? }
```

### Контракт точки

Единый для STR и TXT:

```js
{ id, x, y, z, d: [D1, D2, ...], drill?, code? }

// drill (только для скважин):
drill = { az, dip, depth, actual, end: {x, y, z} }

// code (только для TXT с кодами):
code = 'vb' | 'nb' | 'otm' | null
```

## Парсеры

### `strParser.js`

- Разбор `.str` построчно: строка 0 — заголовок, дальше `id, Y, X, Z, D1..D26`.
- `id === 0` закрывает стринг.
- Порядок полей в файле — **Y, X, Z** (не X, Y!). Меняется галочкой `swap`.
- `STYLES` — карта стилей по номеру стринга. У каждого: `kind` (`line`/`points`),
  `color`, `width`/`size`, опционально `labelField`, `centerD`.
- `computeDrill(p)` — по D9/D10/D23/D4 строит ствол скважины:
  - **D9** — азимут (0° = север, 90° = восток, по часовой).
  - **D10** — наклон (−90° = вертикально вниз).
  - **D23** — фактическая глубина (приоритет над D4).
  - **D4** — проектная глубина.
  - Глубина считается **по стволу**, не проекция.

### `txtParser.js`

- Разбор строк `имя X Y Z [описание]`.
- Первое слово — имя, следующие 3 числа — X Y Z, остаток строки — описание.
- `d = [имя, описание]`.
- При `asLine = true`:
  - Если в описаниях есть коды `vb`/`nb`/`otm` — точки группируются по кодам.
    `vb`/`nb` → линии, `otm` → точки.
  - Линии разрываются, если расстояние между двумя соседними точками > 50 м.
  - Если кодов нет — общая полилиния по всем точкам.

### `pdfOverlay.js`

- `loadPdf(file, pageNum)` — рендерит страницу в canvas.
  Качество: `RENDER_SCALE = 4`, лимит `MAX_CANVAS_PIXELS = 40 МП`.
- Аффинное преобразование PDF→мир: `x = a·u + b·v + e`, `y = c·u + d·v + f`
  (`u`, `v` — пиксели PDF).
- `solveAffine(pairs)`:
  - **2 пары** → подобие (сдвиг + поворот + общий масштаб).
  - **3+ пар** → полное аффинное через МНК.
- `computeRMS` — оценка точности привязки.

### `gridDetector.js`

- Проекция яркости по серым пикселям → поиск пиков → фильтр регулярности.
- Возвращает координаты вертикальных и горизонтальных линий сетки.
- Используется в `georef.js` для автодетекции (резервный вариант привязки).

## Рендеры

### `render2d.js`

- Камера: `{ s, cx, cy, ox, oy }` — масштаб, мировой центр, экранный сдвиг.
- Три прохода:
  - **Pass 0** — линии, стволы скважин.
  - **Pass 1** — точки + подписи полей.
  - **Pass 2** — подсветка выбранной точки.
- `pickPoint(x, y)` — ближайшая точка в радиусе 18 px.
- Измерение — пунктирная линия, стрелки наружу, подпись длины.
- Зум колесом/pinch **в точку под курсором**.
- Тёмная тема: `adaptColor(c, theme)` — тёмные цвета (< 35% яркости) → `#e2e8f0`.

### `render3d.js`

- `WebGLRenderer` + `OrbitControls` (демпфирование, `zoomToCursor: false`).
- Система координат Three.js: `X = восток`, `Y(вверх) = Z съёмки`, `Z = −север`.
- Линии — **fat lines** (`Line2` + `LineMaterial`), реальная толщина в пикселях.
  `LineBasicMaterial.linewidth` в WebGL игнорируется, поэтому `Line2` — единственный способ.
- Точки — `PointsMaterial` с текстурой круга (`makeCircleTexture`).
- Кэш материалов `lineMaterials` (по цвету+толщине) — не плодим одинаковые.
- `setView('top' | 'east')` — фиксированные виды без сброса дистанции.

### `input.js`

- Pointer Events (работает и с мышью, и с тачем).
- Один палец → `onPan`, два → `onPinch(s, cx, cy)`, колесо → `onWheelZoom(cx, cy, factor)`.
- Тап: `moved < 8 px && duration < 400 ms`.

### `pivot.js`

- Ищет ближайшую точку данных **по экранному расстоянию** (30 px).
- Если не попал — проекция луча на горизонтальную плоскость Y = 0.
- При выборе точки вращения сдвигает **и** `camera.position`, **и** `controls.target` на
  одну дельту — дистанция камеры не меняется, скорость вращения не «прыгает».

## UI-модули (`js/ui/`)

### `importFiles.js`

- Определение типа файла по расширению:
  - `.pdf` → PDF (диалог выбора страниц, если их > 1)
  - `.str` → STR
  - `.dwg` / `.dxf` → сообщение «формат не поддерживается»
  - всё остальное → TXT
- **Максимум 10 слоёв.**
- Чтение: UTF-8, при ошибке — Windows-1251 (кириллица из Surpac).

### `layers.js`

- Панель слева (узкая полоска с вертикальным текстом «Слои»).
- Клик по слою — активен (синий фон).
- Иконки: 🔒 блокировка, 👁 видимость, ✕ удалить.

### `fields.js`

- Модал в 2 шага:
  1. Выбор стрингов (галочки, «Выбрать все»).
  2. Выбор до 2 полей + галочка «Округлить до 1 знака».
- Результат пишется в `state.labelConfig`.
- Приоритет над `labelField` из `STYLES`.

### `georef.js`

- Две вкладки:
  - **Ручная** — тап по PDF → тап по точке STR/TXT. До 10 пар. RMS-оценка.
  - **По углам** — пресеты углов сетки по карьерам (ВИ, Б2), координаты
    предзаполнены, можно править. Цепочка тапов: правый нижний → левый нижний →
    левый верхний.

### `survey.js`

- Модал промера БВР.
- **Автозапятая:**
  - Глубина: `1` → «завал», `0` → «не отбур», `2–9` → `X.0`, `10–19` → `XX.0`,
    `20+` → делим на 10.
  - Угол: `0–90` → `X.0`, `>90` → делим на 10.
- Enter → переход к следующей строке той же колонки.
- `enterkeyhint="next"` — подсказка мобильной клавиатуре.
- Автосохранение в localStorage через `surveyStore`.

## PWA (`sw.js`)

- Кеш: `CACHE = 'str-viewer-v5'` (поднимать при изменениях SHELL).
- Стратегия **stale-while-revalidate**: сначала кеш, в фоне обновление.
- `SHELL` — список файлов для кеша при install. Список единый, менять аккуратно.
- **При добавлении нового JS-файла — обязательно добавить в SHELL и поднять версию CACHE.**

---

## Тёмная тема

- Классы и темы переключаются атрибутом `data-theme` на `<html>`.
- CSS-переменные переопределяются в `[data-theme="dark"]`.
- В JS — `state.theme` и метод `setTheme()` у рендеров.
- По умолчанию всегда светлая (без `matchMedia`).
- Цвета в canvas конвертируются через `adaptColor()`.

## Горячие точки изменений

Если нужно добавить:

- **Новый стиль стринга** → `STYLES` в `js/parsers/strParser.js`.
- **Новое поле в словаре** → `STR_FIELDS` в `js/parsers/strParser.js`.
- **Новый тип парсера** → новый файл в `js/parsers/`, подключить в `importFiles.js`.
- **Новую кнопку в тулбар** → `index.html` + обработчик в `app.js`.
- **Новый вид в 3D** → `setView()` в `js/renderers/render3d.js`.
- **Новый модал** → файл в `js/ui/`, добавить разметку в `index.html`.

## Правила разработки

1. **Файл > 250 строк или 2+ ответственности → разделить.**
2. **Не менять контракты точек и слоёв** без обновления всех модулей.
3. **Публичный API модулей (`createRender2d`, `parseStr`, `solveAffine`, …) не менять**
   без необходимости.
4. **При изменениях JS — поднимать версию `CACHE` в `sw.js`** (vN → vN+1).
5. **Не добавлять сборщики** (webpack, vite) и npm-пакеты — проект статический.
6. **Использовать CSS-переменные** вместо хардкод-значений.
7. **Тёмная тема** — все новые цвета проверять в обеих темах.
